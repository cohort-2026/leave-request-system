# Auth and roles

401 means not signed in. 403 means signed in but not allowed. Hiding a button is not security — these checkpoints run on the server.

| Address | Who may call it |
| --- | --- |
| `GET /api/health` | Anyone (no login) |
| `POST /api/auth/register` | Anyone (no login). Always **400**; open staff signup is closed. |
| `GET /api/billing/plans` | Anyone (no login). Public ZAR catalog. |
| `GET /api/platform/companies` | `platform` only. Returns company status, subscription plan/status, seat limit, and seats used (active + pending_verification company users); does not return leave data. |
| `POST /api/companies/signup` | Anyone (no login). Creates a payment checkout, not a company. |
| `POST /api/companies/signup/mock-pay` | Anyone (no login), local only. Completes checkout and creates the company admin. No session cookie. |
| `POST /api/auth/onboard` | Anyone (no login). Token must be an active company invite. Creates `staff` in that company only. |
| `GET /api/companies/current` | Any signed-in company user (`requireAuth` plus a `company_id`). Platform **403**. |
| `GET /api/companies/current/sso` | `company_admin` of a company. Returns `{ issuer, clientId, emailDomain, enabled, clientSecretConfigured }`. Never returns the raw secret. |
| `PUT /api/companies/current/sso` | `company_admin` of a company. Body `{ issuer, clientId, clientSecret?, emailDomain, enabled }`. Omitting `clientSecret` keeps the stored cipher. Never returns the raw secret. |
| `POST /api/auth/sso/start` | Anyone (no login). Body `{ identifier }` (company slug or work email). Local mock only: **200** `{ authorizationUrl }`. Unknown company or SSO off: **404**. `NODE_ENV === "production"`: **503**. |
| `GET /api/auth/sso/start?company=` | Anyone (no login). Same lookup as POST; local mock **302** to the mock authorize page. Production **503**. |
| `GET /api/auth/sso/callback` | Anyone (no login). Mock OIDC callback. Matches an existing user in that company, sets `lrs_session`, skips password and TOTP. Unprovisioned email: **403**. Cross-company email: **403**. Production **503**. |
| `GET /api/companies/current/calendar` | `company_admin` of a company. Returns its seven working-day flags and holidays. |
| `PATCH /api/companies/current/calendar` | `company_admin` of a company. Requires all seven weekday settings as booleans. Staff, managers, and platform are **403**. |
| `POST /api/companies/current/holidays` | `company_admin` of a company. Adds a holiday using `{ date: "YYYY-MM-DD", name }`; duplicate dates in that company are **409**. |
| `POST /api/companies/current/holidays/seed-za?year=2026` | `company_admin` of a company. Restores missing South African public holidays for that year (`source=za`). New companies and calendar reads already seed years **2026–2030**. Sunday holidays are stored on the following Monday with `actualDate` set to the Sunday. Duplicate dates are skipped (`ON CONFLICT DO NOTHING`). |
| `DELETE /api/companies/current/holidays/:id` | `company_admin` of a company. Deletes only a holiday belonging to that company; missing or other-company ids are **404**. |
| `GET /api/companies/current/rules` | `company_admin` of a company. Returns that company’s reviewer, minimum-notice, escalation, and auto-approval rules. |
| `PATCH /api/companies/current/rules` | `company_admin` of a company. Updates valid reviewer settings, a non-negative integer minimum notice, and non-negative quarter-hour timeout values. Zero disables a timeout; when both are enabled, auto-approval must be no earlier than escalation. |
| `GET /api/companies/current/users` | `company_admin` of a company. Same-company people only. |
| `GET /api/companies/current/departments` | `manager` or `company_admin` of a company. Same-company departments (`id`, `name`, `managerId`, `managerName`, `maxOff`). Staff and platform are **403**. Create and manager assignment stay `company_admin`. |
| `GET /api/companies/current/date-blocks` | `company_admin` of a company. Returns `{ dateBlocks }` for that company. |
| `POST /api/companies/current/date-blocks` | `company_admin` of a company. Body `{ startDate, endDate, departmentId, mode, reason }`. `departmentId` null is company-wide. Mode is `block` or `warn`. A department from another company is **400**. Returns **201** the saved block. |
| `PATCH /api/companies/current/date-blocks/:id` | `company_admin` of a company. Same-company block only; missing or other-company ids are **404**. |
| `DELETE /api/companies/current/date-blocks/:id` | `company_admin` of a company. Same-company block only; missing or other-company ids are **404**. Returns `{ ok: true }`. |
| `PATCH /api/departments/:id` | `company_admin` of a company. Body `{ maxOff }` (non-negative integer or `null`). Same-company department only; missing or other-company ids are **404**. |
| `GET /api/leave-types` | Signed-in `staff`, `manager`, or `company_admin` with a `company_id`. Active types for that company only. Platform **403**. |
| `GET /api/admin/leave-types` | `company_admin` of a company. Includes inactive types. Staff and managers are **403**. |
| `POST /api/admin/leave-types` | `company_admin` of a company. Creates a type for that company. Duplicate names are **409**. Extra body fields such as `companyId` are ignored. |
| `PATCH /api/admin/leave-types/:id` | `company_admin` of a company. Same-company type only; missing or other-company ids are **404**. Deactivate with `{ isActive: false }`. Extra body fields such as `companyId` are ignored. |
| `GET /api/companies/current/onboarding-link` | `company_admin` of a company (`requireAuth` + `requireRole`). Does not return the raw token. |
| `POST /api/companies/current/onboarding-link` | `company_admin` of a company. Creates or rotates the hashed invite URL. |
| `POST /api/companies/current/onboarding-link/disable` | `company_admin` of a company. |
| `POST /api/auth/login` | Anyone (no login). Unverified accounts get **403** and no cookie. |
| `POST /api/auth/verify-email` | Anyone (no login). Token from the emailed link. |
| `POST /api/auth/resend-verification` | Anyone (no login). Same success whether the email exists or not. |
| `POST /api/auth/forgot-password` | Anyone (no login). Same success whether the email exists or not. |
| `POST /api/auth/reset-password` | Anyone (no login). Token from the emailed link. Does not set a session. |
| `POST /api/auth/login/totp/enroll` | Anyone with a valid `lrs_mfa` enroll challenge |
| `POST /api/auth/login/totp` | Anyone with a valid `lrs_mfa` login challenge |
| `POST /api/auth/logout` | Anyone (idempotent; no cookie still returns 200) |
| `GET /api/auth/me` | Any signed-in role (`requireAuth`) |

| `POST /api/auth/change-password` | Any signed-in role. Requires the current password. Stays signed in. |
| `POST /api/auth/totp/reset-request` | Any signed-in role. Emails a link; does not wipe TOTP yet. |
| `POST /api/auth/totp/reset-confirm` | Anyone (no login). Token from the emailed link. Wipes TOTP. |
| `GET /api/auth/totp/enrollment` | Any signed-in role with a pending enroll challenge |
| `POST /api/auth/totp/enroll` | Any signed-in role with a valid `lrs_mfa` enroll challenge |
| `GET /api/ping/signed-in` | Any signed-in role (`requireAuth`) |
| `GET /api/ping/admin` | `company_admin` or `platform` (`requireAuth` + `requireRole`) |
| `GET /api/home` | Signed-in `staff`, `manager`, or `company_admin` with a `company_id`. Returns the user's balances, pending request count, and up to five most recent requests. Platform **403**. |
| `GET /api/leave/balances` | Signed-in `staff`, `manager`, or `company_admin` with a `company_id`. Own entitled, taken, pending, and available days for active types. Platform **403**. |
| `GET /api/calendar` | Signed-in `staff`, `manager`, or `company_admin` with a `company_id`. Accepts `month=YYYY-MM` or inclusive `from`/`to` `YYYY-MM-DD` dates (at most 366 days). Optional `scope=team` (default) or `scope=company`. Staff always get team (own leave plus the same department and departments they manage). Manager and `company_admin` default to team and may pass `scope=company` for the whole company. Optional `departmentId` is manager or `company_admin` (**403** for staff, **404** if the department is not in the company). Returns holidays, leave ranges, and overlapping `blocks`. Staff see team leave with `type: null` for colleagues. Platform **403**. |
| `GET /api/leave/preview?leaveTypeId=&start=&end=` | Signed-in `staff`, `manager`, or `company_admin` with a `company_id`. Counts working days on the requester's company calendar. Platform **403**. |
| `POST /api/leave` | Signed-in `staff`, `manager`, or `company_admin` with a `company_id`. Creates the request for the signed-in user only, checks dates/overlaps/available balance/company rules, and notifies the assigned reviewer. Pending days reserve balance. Unpaid types skip balance checks and changes. If the requester is a `company_admin` and no other eligible reviewer exists, the request is saved as **approved**, the paid balance is reduced, and no reviewer email is sent. Staff and managers still get **409** when no reviewer exists. A leave type from another company is **403**. Platform **403**. |
| `GET /api/leave` | Signed-in `staff`, `manager`, or `company_admin` with a `company_id`. That user's own requests only, newest first. Platform **403**. |
| `GET /api/team/queue` | `manager` or `company_admin` with a `company_id`. Manager: pending requests for **staff** in departments they manage plus requests explicitly assigned to them after escalation, excluding their own. `company_admin`: all pending in the company except their own. A manager's own leave is decided by `company_admin`. Staff and platform are **403**. |
| `GET /api/leave/:id` | Owner of that request, the assigned reviewer, a `manager` who can see it in the team queue, or a same-company `company_admin`. Other-company ids are **404**. Same-company callers who are none of those are **403**. Missing ids are **404**. |
| `PATCH /api/leave/:id` | Owner, `pending` only. Re-runs book-leave checks and replaces the stored working-day count. Multipart body matches submit (`leaveTypeId`, `start`, `end`, `reason`, optional `file`, optional `removeFile=true`). Other-company or non-owner ids are **404**. Non-pending items are **400**. |
| `POST /api/leave/:id/cancel` | Owner, `pending` only. Sets `cancelled_at`; its reservation is released because only pending requests count toward pending days. Emails the assigned reviewer when one exists; missing reviewer skips mail. Other-company or non-owner ids are **404**. Non-pending items are **400**. |
| `POST /api/leave/:id/approve` | Allowed reviewer only (the original reviewer, an explicitly escalated same-company manager, or same-company `company_admin`). Status updates to approved; paid types decrease `days_remaining` and increase `days_used` by the stored working-day count, moving the days from pending to taken. Unlimited types do not change balances. Self-approval or cross-company targets are **403**. Non-pending items are **400**. Missing requests are **404**. |
| `POST /api/leave/:id/reject` | Allowed reviewer only (the original reviewer, an explicitly escalated same-company manager, or same-company `company_admin`). Requires a non-empty `decisionReason` in the body, otherwise **400**. Status updates to rejected; its reservation is released because only pending requests count toward pending days. Self-rejection or cross-company targets are **403**. Non-pending items are **400**. Missing requests are **404**. |
| `POST /api/dev/run-leave-escalations` | Local development only; `company_admin` runs due timeout actions for their own company. Production responds **404**. |
| `GET /api/users/:id/balances` | Owner of that row, or `manager` / `company_admin` in the same company. Staff may not read another id. Other-company ids are **403**. Missing users are **404**. Platform **403**. |
| `GET /api/users/:id` | Owner of that row, or `manager` / `company_admin` in the same company, or `platform`. Staff may not read another id. Failed checks are **403**. Missing rows are **404**. `password_hash` is never returned. |
| `PATCH /api/users/:id/role` | `company_admin` of a company. Same-company target only. Cannot change own role, assign `platform`, change a `platform` user, or demote the last `company_admin`. |

Roles are `staff`, `manager`, `company_admin`, `platform`. There is no generic `admin` role.

`companies` and `users.company_id` exist. Same-company checks for manager / company_admin use `users.company_id`. Invite links, people list, and role change are keyed by `company_id`. `users.company_name` stays as a display copy of `companies.name` and is not used for authorization. Platform can read any row, is not in a company, and cannot list people or change roles. Staff join through an invite (or later SCIM / SSO), not `POST /api/auth/register`. A role change does not skip email verification or TOTP and does not set a session.

Calendar responses contain the seven `mondayIsWorking` through `sundayIsWorking` booleans and `holidays: [{ id, date, name, source, actualDate }]`. `source` is `custom` or `za`; `actualDate` is the Sunday a ZA holiday fell on when the stored `date` is the observed Monday. South African public holidays for 2026–2030 are inserted when a company is created, when an existing company first reads its calendar or leave preview, and by `029_za_public_holidays.sql`. PATCH returns the full calendar; POST returns `{ holiday }`; seed-za returns `{ year, added, holidays, observed }`; DELETE returns `{ ok: true }`.

Leave type list responses are `{ leaveTypes: [{ id, name, defaultDays, hasBalance, cycleMonths, colour, allowancePeriod, isActive, allowBackdate, requiresDocumentAfterDays, ignoresBlocks }] }`. `colour` is one of `violet`, `rose`, `amber`, `sky`, `slate`, `teal` (`color` is accepted as an alias on write). POST returns **201** `{ leaveType }` and PATCH returns `{ leaveType }`. New companies created at mock-pay receive the five defaults (Annual, Sick, Family responsibility, Unpaid, Study). Seeded Sick and Family responsibility types have `ignoresBlocks: true`.

Leave balance list responses include `{ balances: [{ leaveTypeId, leaveType, entitled, taken, pending, available, hasBalance, cycleLabel }] }` and retain `totalAllowance`, `usedDays`, and `daysRemaining` compatibility aliases. Pending is summed from pending leave requests, not stored; available is `entitled - taken - pending`, and is `null` for unlimited types. Paid signup, invite onboarding, and leave-type creation initialize entitlement rows. Remaining is never taken from the client.

Working calendar settings and holidays are also scoped by `users.company_id`. `countWorkingDays` in `backend/leave/workingDays.ts` counts an inclusive date range using those weekday flags and skips matching holiday dates.

`GET /api/calendar` returns `{ holidays: [{ date, label, name }], leave: [{ id, personId, name, start, end, startHalf, endHalf, status, type }], blocks: [{ id, start, end, startDate, endDate, departmentId, departmentName, mode, label, reason }] }`. Pass `month=YYYY-MM` or inclusive `from`/`to` `YYYY-MM-DD` dates, at most 366 days, with `from` on or before `to`. Optional `scope=team` (default) limits leave to the viewer, people in their department, and people in departments they manage. `scope=company` is manager and `company_admin` only and returns the whole company. Optional `departmentId` further limits leave to that department. Holidays are that company's `public_holidays` in range (`label` is the stored name). Leave is one range per overlapping `pending` or `approved` request (weekends and holidays included; rejected and cancelled are omitted). The browser expands ranges onto days. Staff `type` is `null` for a colleague and the leave type for their own request; manager and `company_admin` always receive the leave type. Names prefer `display_name`, then `Colleague` (email is not returned). `blocks` are overlapping `date_blocks`. Team scope shows company-wide blocks plus the viewer's department and departments they manage. Company scope shows every block in range. `departmentId` keeps company-wide blocks plus that department. A Durban department block does not appear for Johannesburg staff on team scope.

Leave preview returns `{ workingDaysCount, availableAfter, warnings, noticeWarnings }`. `availableAfter` is the remaining balance after this request, or `null` for unlimited types. `warnings` is `{ kind: "block" | "warn" | "clash", message }[]` from date blocks and department `max_off`. Sick and Family responsibility (`ignoresBlocks`) skip block and warn kinds. A `block` warning on submit or pending edit is **400** with that reason. `warn` and `clash` allow submit and are returned on the created request, team queue, and review detail so a reviewer can see them. `noticeWarnings` remains the string list for backdate, notice, balance, and empty-range messages. Leave submission accepts `leaveTypeId`, `start`, `end`, `reason`, and an optional multipart `file` (PDF/JPG/PNG/HEIC, maximum 4 MB); it calculates and stores its own working-day count and returns `{ leaveRequest, warnings }` with **201**. Requests with no working days are rejected. Paid requests are checked against `entitled - taken - pending`; unpaid (`hasBalance: false`) requests skip balance checks and do not change balances on approval. File bytes are stored in `leave_documents.file` (BYTEA). `GET /api/leave/:id/file` streams the attachment for the owner, assigned reviewer, or same-company HR and writes one `leave_document_access` row. Other same-company colleagues receive **403**; other companies receive **404**. `GET /api/leave/:id/file/access` is `company_admin` only. JSON never includes a filesystem path. A supporting file is required when working days are **greater than** `requires_document_after_days` (Sick: 2 days without a file is allowed; 3 days is not). Unsupported types return **415**. A reviewer notification failure after save is logged rather than returning **502**. A sole `company_admin` request is returned with `status: "approved"`, `reviewed_at` set, and decision reason `Automatically approved because no other eligible reviewer is available`.

Team queue returns a JSON array of `{ id, employeeName, startDate, endDate, workingDays, leaveType, status, submittedAt, supportingFileName, balanceAfter, clashCount, warnings }` with `id` as a string. Requests are ordered oldest first, and a user's own requests are excluded. `GET /api/leave` and owner `GET /api/leave/:id` return `{ id, employeeName, leaveTypeId, leaveType, startDate, endDate, workingDays, reason, supportingFileName, status, submittedAt, decisionReason, warnings }` (`id` is a string). Reviewer detail also includes `balance: { available, afterApproval }`, `teamOverlaps`, `warnings`, and `events`. Overlaps are computed by the server from same-company, same-department pending or approved leave; no browser-side fetch of other employees' leave is needed. Events are rows from append-only `leave_request_events` (`id`, `type`, `before`, `after`, `balanceDelta`, `createdAt`, `actorUserId`, `actorName`). There is no PATCH or DELETE for events. Approving emails the requester; rejecting includes the decision reason. Cancel emails the reviewer when one is assigned.
